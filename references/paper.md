# 论文格式 Word 与数值呈现

适用范围：把已计算、已审查的统计结果组织为学术方法与结果，生成可编辑 `.docx`。不要先写结论再挑结果。没有真实数据时只制作分析计划、语法或明确标识的演示，不补造研究结果。

## 结构与写作边界

优先读取学校或期刊说明及用户给的 `.docx`；这些决定章节、字数、引文规范、字体和表格格式。用户仅要“论文格式”时采用以下可调整基线，不声称存在唯一通用论文格式：

- A4，四边 2.5 cm，正文中文宋体类字体、英文与数字 Times New Roman，12 pt、1.5 倍行距，黑色标题；紧凑三线表，不加竖线。当前 Mac 默认字体为 Songti SC；其他系统按实际字体可用性配置。没有实际字体时先解决替代并检查字形。
- 完整论文按真实材料组织题目、摘要与关键词、引言、资料与方法、结果、讨论、结论、参考文献、必要附录。仅要求统计分析时交付方法、结果、表图及复现附录，不为凑齐章节虚构文献综述、假设、伦理审批、抽样过程或研究意义。
- 研究设计与资料来源、纳入排除、变量定义、编码与量表计分、缺失值、权重与聚类、统计方法和推断设置，应与代码完全一致。区分预设、敏感性和探索性分析。
- 结果段先回答研究问题，再指向表图。讨论区分估计大小、精度、统计证据和实际意义；观察性关联不自动写成因果效应。“不显著”不证明无差异或等价，等价／非劣效需要预先界值及适当设计。

## 结果呈现合同

每个模型／检验的表图值都要能定位至全精度结果中的分析 ID、字段或原生输出单元格。不要人工把 Word 当作第二个计算源。正文、表格、图注和摘要取自同一结果对象。

| 结果类型 | 应报告的内容 |
| --- | --- |
| 样本与描述 | 初始与最终 N，剔除与缺失原因；每个模型的有效 N；分类 n 与分母明确的百分比；连续变量均值和样本 SD，或按分布和目的报告中位数与四分位距 |
| 均值或比例比较 | 估计差及方向、CI、适当效应量、检验统计量和 df、p；检验类型及配对／独立、等方差／Welch、校正方法 |
| 回归与广义模型 | 结局编码、参考组、估计值及单位、SE 类型、CI、p、样本量；OR／RR／IRR／HR 标明指数变换；不混淆边际与条件效应、概率差与优势比 |
| 量表与因子模型 | 题目数量、反向题、缺失策略、相关矩阵类型、估计与旋转方法、因子保留依据、载荷和模型适配信息；不要把高 α 当成单维性证明 |
| 中介调节与 SEM | 理论方向、估计方法、间接效应 CI 算法、bootstrap 规则和次数、交互编码与条件效应；乘积项与简单斜率不可互代；拟合失败不可隐藏 |
| 纵向面板与生存 | 分析单位、时间／事件定义、删失与风险集、聚类／随机结构、个体和观测数、时间效应及关键模型诊断 |
| 复杂设计或缺失处理 | strata、PSU、权重类型、设计 df、合并规则、插补次数及合并推断；普通 N 不能替代有效设计信息 |

报告与选择方法均参考目标软件手册及适用研究报告规范。只有实际检查过的假设、诊断、收敛与敏感性结果才写“已检查”。模型因数据问题未能估计时说明原因，不用零值补齐。

## 数字与三线表

- 全精度计算与保存，展示阶段才舍入。通常估计值与 SE／CI 保留两至三位，p 保留三位；尺度很小时调整位数或科学记数，避免把非零效应显示成零。报告时一张表内统一精度和单位。
- `p=0.000` 改为 `p<0.001`；严格意义上极小 p 的数值需要取自可靠尾概率算法，不靠减法抵消。p 的显示不能作为推断源。内部结果必须保留原值，不能从星号或已舍入的 `.000` 反推原始值。仅有原生显示 p 值时注明其精度限制。
- 置信区间写清置信水平和算法。非对称 CI 不人为变对称。无定义、不可估计与缺失有不同原因，表中用破折号并注释；不得填 0 或制造 p 值。
- 表题在表上方，注释在下方；仅表顶、表头下、表底三条横线。分类参考组、星号阈值、多重比较校正、SE 类型、CI 水平和有效样本在注释中解释。显著性星号为可选，不能代替估计值与不确定性。
- 图题、轴名、单位、分组、误差条定义、样本量及 CI 水平齐全。避免无意义 3D 图、截断造成误读的坐标，以及将 SD／SE／CI 不作区分的误差条。

## 构建器与 JSON 规格

`scripts/build_report.py` 是排版辅助，不实现统计计算或认证原生对照。先看可运行规格 `assets/report-spec.example.json`。输入为 UTF-8 JSON，版本 `1.0`；未知字段、重复键、非有限数、非法数值类型及不齐的表格行会被拒绝。

```bash
python scripts/build_report.py report.json --validate-only
python scripts/build_report.py report.json --output 分析报告.docx
```

`--validate-only` 不生成文件；输出已存在时需另取文件名或明确使用 `--force`。使用 Codex 时先调用工作区依赖工具获取 bundled Python 和 `python-docx`，不要将本机绝对路径写进可复用报告规格。其他环境使用已具备 `python-docx` 的 Python。无需为探测或比对安装 Word 依赖。

顶层必填：`schema_version`、`title`、`status`、`provenance`、`sections`。可选：`subtitle`、字符串数组 `keywords`、按目标引用格式整理的字符串数组 `references`、`style`。缺失章节不自动补写。

- `status` 对应主指南的 `NATIVE_EXECUTED`、`VERIFIED_MATCH`、`REIMPLEMENTED_UNVERIFIED`、`BLOCKED`；专用演示可用 `SYNTHETIC_DEMO`。该字段由分析工作流提供，构建器不会因为 JSON 填了某个状态就证明该状态为真。未核验与演示状态会显著显示，所有状态写入复现附录。一个报告含不同核验状态的模型时，在方法／结果或核验附录逐个标明状态，并使用保守的总体状态或拆分报告；只有所有被声称已匹配的分析均已通过时才用整体 `VERIFIED_MATCH`。报告规格与 `compare_results.py` 的严格比较规格用途不同，不能直接互换。
- `provenance` 必填字符串：`data_description`、`engine`、`engine_version`、`analysis_code`、`verification`。可选 `data_sha256`、`comparison_report`、`analysis_plan`、`notes`，以及非负整数 `random_seed`。两种已执行／已匹配状态要求数据 SHA256；`VERIFIED_MATCH` 另要求对照报告标识。字段可存相对文件名或简短内容；构建器只记录，不验证这些证据是否真实、完整或通过。完整证据随复现文件交付。
- `style` 可设置 `body_font_zh`、`body_font_en`、`body_size_pt`（9–16）、`line_spacing`（1–2）、`margin_cm`（1.5–3.5）。它仅调整基线，不能读取并完整复刻用户 DOCX 模板。用户提供模板时走 documents skill 的模板工作流，不声称此脚本支持模板导入。
- `sections` 是非空数组。每项含 `heading`、可选 `level`（1–3）、非空有序 `blocks`。
- 段落块：`{"type":"paragraph","text":"正文"}`。
- 表格块：`type="table"`、`caption`、`columns`、`rows`，可选字符串数组 `notes`。列定义为 `{"label":"均值","align":"center","width_cm":2.5}`；`align` 可为 left／center／right，默认 center。宽度要么全部指定，要么全部省略，总宽不得超过页面可打印宽度。最多 12 列，宽表需另行横向页面或拆为合理子表；不可直接缩小至不可读。
- 图块：`type="figure"`、`caption`、`path`、`alt`，可选 `width_cm` 和字符串 `notes`。仅 PNG／JPEG；路径相对 JSON 所在目录且不得越界，默认宽度不超过 14 cm；超高图仍需渲染检查并调整。构建器不生成图、不下载远程图。

表格单元格可为字符串、有限数或 `null`；`null` 显示破折号，其原因须在表注说明。可用带格式的对象避免手动舍入：

```json
{"value": 1.5811388300841898, "format": "number", "digits": 2}
{"value": 0.00024, "format": "p", "digits": 3}
{"value": 0.125, "format": "percent", "digits": 1}
{"value": 5, "format": "integer"}
```

上述依次显示 `1.58`、`< 0.001`、`12.5%`、`5`。`percent` 输入必须是待乘 100 的比例，不能把已经百分化的 12.5 再传入。`p` 数值限 0–1；整数格式拒绝小数。数值格式采用十进制四舍五入，去除显示负零。不要把正式 p、CI 等预格式化为字符串以绕开数值保存。

输出同时生成 `分析报告.traceability.json`，保留完整输入规格、原始单元格数值、输入与 Word 的 SHA256、生成时间，并明确声明构建器不认证统计正确性。该文件是 Word 的追溯副本，不取代分析合同、原生输出、分析代码或对照报告。逐页渲染审查完成后，把布局验收记录留在复现资料中；不要声称侧车文件已经包含没有执行过的视觉检查。

## Word 交付前的验证

1. 对照全精度结果、日志和有效样本复核每个表、图、正文数值与方向；检查标签、单位、CI 水平与单双侧。
2. 使用可用的 documents skill、其 `render_docx.py` 及 bundled 渲染依赖逐页生成 PNG。只能使用该环境配套的 LibreOffice；不要降级到用户桌面安装的 LibreOffice。先从工作区依赖工具解析路径，按 documents skill 完成作者操作标记。
3. 打开每一页检查缺字、截断、跨页表头、三线表、图注、标题孤行、留白、页边距和字体。修改后重新渲染并检查受影响页面；最终版本必须每页检查。
4. 正式交付 `.docx`，同时提供该次实际分析的代码和追溯资料。没有可用渲染环境时明确交付状态，不能写“已逐页验收”。PNG 与 PDF 默认只作内部排版验证材料，不冒充用户要求的 Word。

若系统已安装中文字体而渲染页仅有英文或空方框，先检查渲染日志和 PDF 的实际字体列表。Bundled LibreOffice 的 fontconfig 默认路径可能在运行时迁移后失效；应为该次渲染进程将 `FONTCONFIG_FILE`、`FONTCONFIG_PATH` 指向配套 Resources/fontconfig 中的配置，必要时用任务工作目录作字体缓存。路径从实际 bundled 运行时解析，不修改系统字体配置或换用桌面 LibreOffice。重新渲染后仍须逐页检查。
