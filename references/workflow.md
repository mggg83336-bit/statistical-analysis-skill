# 分析合同与方法扩展

## 输入与数据审计

先读取用户提供的文件和字典，列出研究问题、主要终点、研究设计、分析单位、变量类型与编码、时间和聚类结构、纳排标准、权重、目标软件版本、交付模板。优先从材料中确定。缺少决定估计目标的条件时集中询问；格式默认、目录组织等不用等待批准。

原始文件只读，生成校验和；清洗在副本进行。检查 Excel 多表头与公式缓存、日期序列与时区、CSV 编码和分隔符、SPSS 用户缺失值和标签、Stata 的 `.` 与 `.a`–`.z`、字符串空值、浮点精度和重复 ID。ID 相同不一定是重复观测，须结合随访和数据结构。保存变量字典、缺失分布、范围和频数，分类变量不可直接按连续数值解释。

按模型建立分析样本：记录原始 n、每一步排除的原因和 n、最终有效 n、聚类数及加权 n（各自标识）。双变量 pairwise 分析要保留每对 n，不能以一个总 n 代替。多重插补保留 m、插补模型、迭代、种子和各插补样本；不把插补数据叠成独立样本。

对齐两种实现时，用类型一致的稳定行键或内部行号和**相同的哈希生成程序**建立 sample hash；数据 hash 包含变量取值及顺序，分析合同另包含变换、编码、权重。仅 n 相同不足以证明样本相同。没有原生行级证据时不能填写猜测的相同 hash。哈希只用于本地追溯，不是匿名化保证。

## 分析合同

在运行前保存 `analysis-plan.json` 或同等结构，至少包含：

- `analysis_id`、研究问题、估计目标（estimand）、预设或探索、主要与次要分析。
- `target`：SPSS／Stata，版本与补丁、模块、命令及扩展包版本；对已有输出复核时用该输出的版本。
- `data`：来源文件校验和、变量字典、分析样本定义、行键、数据转换与精度。
- `specification`：公式、因变量与自变量、交互、截距、类别顺序／基准、缺失规则、权重类型、聚类／分层／PSU／面板／时间结构。
- `estimation`：估计器和目标函数、优化算法、起始值、迭代上限、收敛阈值、秩处理、ML／REML、分布／link／offset 等适用设置。
- `inference`：协方差估计及修正、df、检验分布、单双侧、alpha、CI 与多重性调整方法。
- `random`：seed、RNG、抽样单位、重复数、重采样索引文件或其 hash；不适用时为明确的 none。
- `required_results`：须比对的样本数、参数、SE、检验统计量、df、p、CI、效应量、拟合指标及诊断；非适用项注明原因。
- `validation`：原生基准来源／版本／代码／日志／文件 hash、数值容差与显示精度；容差在看差异前确定，不能为通过而放宽。

参考 `comparison.md` 的比较 JSON 是合同的比对投影，不替代研究计划。软件侧元数据（candidate 的 Python 版本与 reference 的 Stata 版本）应不同；目标分析合同和统计定义必须相同。契约中不能掩盖结果提取器误读表行或变换尺度的事实。

## 执行与核对

1. 先运行数据检查和最小模型；检查设计矩阵列名、顺序、基准组、变量变换、模型 rank。
2. 执行主分析；检查返回码、日志错误、警告、收敛、边界解及实际样本。退出码为零不保证全部过程成功。
3. 保存未经格式化的数值及其表／行／列／尺度映射。原生输出若只有三位小数，只能做显示精度核对，不能倒推出全精度数值。
4. 有基准则运行 comparator；解析小例、独立实现、单位变换不变量或模拟检查可增加信心，但不等同原生对照。比较不能复用同一个结果文件充当双方独立证据。
5. 不匹配时依次检查样本、编码／权重、模型矩阵、估计器、协方差与 df、统计检验、优化／随机数、提取器、舍入。定位后修改分析或如实记录差异；关键项未通过不发布 VERIFIED_MATCH。
6. 结果表和论文文字统一从同一份结构化结果生成，重新核对正文每个 n、系数、p 和区间；禁止复制旧模型数字或手工“修正”显著性。

## 覆盖未列出过程的扩展协议

“所有能代码实现的分析”通过**按版本查官方过程并扩展**承接，而不是假设一份固定清单已经实现所有算法。

1. 从目标版本的完整命令索引定位命令；确认是 Statistics、Amos、Modeler、Stata 内置还是第三方扩展，检查模块和版本。产品不支持的分析不能假装由它原生计算。
2. 阅读官方命令语法及算法／Methods and formulas，摘录与本任务有关的公式、默认值、选项、限制和资料链接；不要拷贝整本手册。目标版本没有该过程则写明。
3. 原生可用时生成并执行该命令，保留可解析原生输出。需要复现时选择公开定义且有合适实现的算法，将每个关键参数映射到目标定义。无法确认算法或可靠库时生成原生语法并标明尚未执行，停止该分析的数值结论。
4. 按方法风险选择验证例：正常例，以及会改变该方法推断的缺失／类别不均衡／秩亏／ties／权重／聚类／边界／随机等相关情形。仅与当前方法相关，不强迫每项跑全套。
5. 将通过的“命令＋版本＋选项＋数据范围＋容差＋证据”加入任务验证记录。实际新增通用实现须测试；不在用户不知情时更改已有 skill 或全局配置。

## 复现包

建议结构：`analysis-plan.json`、`data-dictionary`、`code/`、`logs/`、`results/full_precision.json`、`validation/`、`figures/`、`报告.docx`。记录运行时间、OS、软件与包版本、完整调用命令、随机状态、脚本 hash 和输入 hash。路径用配置或相对路径，不写凭证或真实身份信息到普通报告。数据按授权留在原处；不为打包复制不必要的敏感原始数据。

目标方法入口见 [Stata 官方文档](https://www.stata.com/features/documentation/index.html) 和 [IBM SPSS Statistics 31 文档与算法目录](https://www.ibm.com/support/pages/ibm-spss-statistics-31-documentation)。链接核实于 2026-11-01；31 仅为可用入口，不是自动指定用户版本。
